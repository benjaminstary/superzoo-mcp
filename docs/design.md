# Design

The server exposes five read-only tools: product search, product detail, per-store availability, product comparison, and common-store matching. A fixed market table selects the official storefront, search language, currency and sale restrictions. Country is fixed for the process lifetime; there is no arbitrary upstream URL input. SK is the default; CZ and PL are also verified.

The native-fetch API client owns encoding, upstream response validation and normalization. A single request policy per long-lived client owns shared concurrency, deadlines, retries, deduplication and caching. Public price offers retain their upstream variant label, including conditional family prices. Unknown stock and enrichment failures remain explicit. Search caps raw candidates at 200 and enriches ordered windows of at most four products, continuing until filters fill the requested limit or candidates end. Exact case/accent-insensitive brand, inclusive decimal-string price bounds, and verified explicit delivery availability combine locally. Missing required filter fields and detail failures cannot match active filters. No-filter searches retain partial discovery records. Coverage and attempted/failed enrichment counts stay explicit; conditional offers retain their upstream labels.

The request policy permits four upstream operations and 128 queued operations. A 15-second deadline covers queueing, at most two attempts, retry delays and body validation. Network failures and HTTP 429/502/503/504 may retry, honoring valid Retry-After only within the deadline or using 200–500 ms jitter otherwise. Successful details cache for 60 seconds and raw stock for 15 seconds in one 256-entry LRU cache keyed by market, operation and variant ID. No search cache, failure cache, or expired fallback exists. Cached records retain original checked_at values; city filtering follows retrieval. Identical detail/stock work is shared, with independently cancellable subscribers; upstream work aborts only after the last subscriber leaves.

Shopping aggregation reuses client methods with at most four local lookups. Comparisons retain input order and per-product errors. Store matching uses stable IDs and the union of observed stores; first successful observation in input order supplies display metadata. Every store includes every requested variant. Missing observations and failed lookups remain null/unknown, with failures preventing all_in_stock. Only explicit inStock for every product permits true. Batch checked_at is completion time; nested observations keep their original times.

The same tools run over stdio or stateless MCP Streamable HTTP using the official SDK. A fresh MCP instance and transport handle each HTTP request, with no shared session state. Native Node HTTP validates Host/Origin, limits JSON body size and closes protocol instances when outgoing responses close. SDK protocol closure aborts handler signals, which flow into client and shopping methods; incoming body completion never triggers cancellation. Protocol cancellation over stdio uses the same signals. Separate HTTP callers retain independent subscriptions to shared upstream work. HTTP binds to loopback by default and has no application authentication. Remote TLS, authentication and request limits belong to deployment infrastructure, as requested.

Keep runtime source in strict TypeScript on Node.js 22+. Compile to `dist/` JavaScript for stdio, HTTP and the package executable. Infer upstream types from Zod validation and type market/configuration boundaries. Tests exercise compiled modules. Docker uses a separate compiler stage, so production only needs JavaScript and runtime dependencies. Native HTTP avoids adding another framework. Environment settings select the market, transport and listener; upstream hosts remain allowlisted in code. Fixtures are reduced public facts, not redistributed app code or copied product descriptions.

See README.md for the configuration and response contract, and investigation.md for API evidence and market limitations.

All tools declare Zod success output schemas and retain JSON text alongside structuredContent. Typed tool failures return stable JSON error payloads as text with isError, outside success schemas. The SDK validates whole input schemas, including cross-field price ranges. Existing input validation remains separate from upstream tool errors.

Request diagnostics write only market, operation, bounded status, duration and cache-hit data to stderr. A separate daily/manual GitHub Actions smoke matrix checks SK/CZ/PL sequentially, with bounded operation summaries and a five-minute job limit. Offline tests remain on Node 22 and 24. A separate package-install CI gate installs the real tarball into a temporary consumer and exercises its executable with fixtures; only dependency installation may access the npm registry. Process tests verify the existing SIGTERM behavior: stdio closes immediately; HTTP stops listening, drains for up to five seconds, then force-closes connections so remaining subscriptions cancel. Queued operations never start after cancellation. GET /health remains process health only. Unit prices, pagination, distance ranking and Polish price-level changes remain deferred; evidence is recorded in investigation.md.
